# Static Routing G01 - implementation and evidence

The owner asked to continue https://buananet.com/mikrotik-static-routing.html, then explicitly asked for YouTube, TikTok and every other option to be copied. After manual Premium login, Playwright exercised all 47 selectable applications across ROS6/ROS7 and TLS-HOST/CONTENT: 188 combinations. Only rendered generator output was observed; generator JavaScript was not extracted. Full rendered output remains in ignored runtime; tracked evidence contains ordered command parameters.

## Implemented

An independent PHP module validates the five fields and creates STEP 1/STEP 2. The Admin preview is `/admin/tools/static-routing/preview`. Public generation and history creation remain locked by reviewed code. The input rejects unknown fields, invalid IPv4 gateways, array-valued selections, executable fragments and reserved/unsafe routing marks. This deliberately tightens reference input acceptance.

184 available cases match the observed ordered route/table/LOCAL-IP/mangle add-parameter projection. The four Shopify app/ROS/matcher cases are blocked because its TLS and CONTENT dataset URLs both returned HTTP 404. There is no substitute dataset. Projection matching is not exact text or complete semantic equivalence.

Dataset acquisition was separate from browser observation: 92 of the 94 public `.rsc` URLs referenced by the generator returned firewall configuration. Their functional parameters were parsed with a narrow allowlist: RAW/address-list add commands and removals scoped to the selected application's list. The original source files, headers and descriptive comments are not bundled. Parameter order and duplicate commands are retained. This is a source-attributed snapshot, not independent dataset authorship, an independently verified application classifier, or a legal license attestation. The manifest records owner-request context, source URLs, download hashes and parameter hashes. Public release/legal review remains outstanding.

The source contains 47 application choices. 46 have two snapshots each: YouTube/TikTok and the remaining streaming, social-media, commerce, conferencing and other-IP choices; Shopify is the explicit exception. All options stay visible so an unavailable source is shown honestly.

## Self-hosted artifacts

The PHP renderer emits its own safely quoted `.rsc` artifact from parameter data. STEP 1 points to the configured NANSAN application origin at `/datasets/static-routing/{sha256}.rsc`. It never hotlinks Buananet. The endpoint serves only known content hashes and is closed in production until G01 is published in reviewed code. It does not take a user-provided URL, filename or script. Parameter file integrity is checked before rendering; stale/tampered data fails closed.

File names use the Nansan prefix and include the match mode. Mangle ownership comments use `NANSAN-G01-<application>` instead of the reference brand. Those URL/file/comment differences are explicit. The original list names are retained because they connect the dataset with the routing rule. Importing the dataset removes and recreates that selected application's RAW/address-list entries, which can conflict with an existing installation.

The current staging origin is SSH-only localhost. A real router cannot use that origin as a general download endpoint. A reachable owned HTTPS deployment and production data review are required before operational use.

## Reproducibility

Run these only in the authorized reference workflow; they are not runtime network jobs:

1. `node scripts/audit-static-routing.mjs` after manual Premium login in the protected audit browser.
2. `node scripts/collect-static-routing-data.mjs` to download the public URLs into ignored runtime without executing them.
3. `node scripts/prepare-static-routing-data.mjs` to parse the allowlisted functional parameters.
4. `php scripts/index-static-routing.php` to index compiled content hashes.
5. `php artisan test --filter=StaticRoutingTest` and the relevant browser suite.
6. `php tests/Support/export-lab-static-routing.php`, then `node scripts/static-routing-lab.mjs 6.49.19` / `7.25`, one VM at a time.

## Verification limits

The disposable lab stages the independently rendered dataset via SFTP over a loopback-only management forward, then runs actual `/import` and generated STEP 2 commands. No physical router or Internet target is accepted. A sentinel mangle rule is present in the regular cases; the reference's literal `place-before=*0` is tested as rendered. An empty-table scenario is checked separately, without assuming an internal item ID. The main cases execute safely rendered parameter data. Four separately hash-checked original public Teams/Telegram RSCs were also imported in an isolated ROS7 run and reproduced the duplicate-entry failures. Snapshot overlays are discarded and owned VMs are stopped after each run.

RouterOS reports are `docs/lab/STATIC-ROUTING-6.49.19.json` and `STATIC-ROUTING-7.25.json`. Record failures as failures. These checks do not establish STEP 1 HTTPS fetch behavior, fresh/accurate application prefix ownership, actual application traffic capture, ISP routing, repeated import safety or capacity. Broad shared network prefixes may classify traffic beyond a single named app. No generator is marked COMPLETE or promoted automatically.

Final main lab results: 186 cases, 182 passed and four ROS7 Teams/Telegram imports failed on duplicate address-list additions. All 93 ROS6 cases passed after SFTP file visibility was explicitly awaited; earlier file-inventory synchronization failures were lab artifacts. Four additional original-source ROS7 tests reproduced the failures. See ../lab/STATIC-ROUTING-RESULTS.md and G01-DUPLICATE-DECISION.md. No duplicate rewrite has been applied; the original prompt requires an owner decision first.

The UI clears old output whenever an application, parameter, template or reset changes it, and discards delayed responses for a previous input revision. Browser coverage includes unavailable Shopify and an intentionally delayed response, so the previous application script cannot remain visible as a result for the new selection.
